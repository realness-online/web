# realness-ops tooling (curated)

Small Firebase Functions project (realness-functions) + marketing/ops
tooling. Run scripts from `apps/realness/tools/ops`, or use the product's
`traffic`, `ads`, and `test:functions` commands. Functions live at
`apps/realness/functions`; this package delegates with `npm --prefix ../../functions`.

## Diagnose / test

- `npm run lint` / `npm run test` (proxy to functions). `test:coverage`, `test:watch`.
- `pre-commit` runs lint + test.

## Deploy / logs

- `npm run deploy` - `firebase deploy --only functions`.
- `npm run logs` - `firebase functions:log`.
- `npm run serve` - firestore emulator, functions only.

## Ops tools (this folder)

- `npm run traffic` - hosting traffic metrics (`node hosting-traffic.js`).
  Example: `npm run traffic -- --cache-only --days 14 --by-day`.
- `npm run ads` - OpenAI ads metrics (`node tools/ads-metrics.js`).
  Needs `OPENAI_ADS_API_KEY` (in ~/.zshrc).

## Note

- `ads.md` documents the ad structure (campaign → ad group=topic → creative).
- Product `firebase.functions.json` owns Functions config; hosting stays in `frontend/firebase.json`.
- Product `firebase.functions.test.json` owns the Functions test emulators.
- `functions/` depends on `@realness.online/thoughts`, published from the
  `apps/realness/frontend` repo. Bump this pin only after that package is live, and run
  `npm --prefix ../../functions install` so the lockfile follows. Release it by pushing
  a `thoughts-v<version>` tag there - never `npm publish` by hand.
