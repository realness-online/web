# Realness tooling (curated)

Product source lives in `src/<domain>/`: `src/app`, `src/chat`, and `src/terminal` for the browser. `frontend/` keeps build configuration, tests, public assets, packages, and platform files.

- `src/settings/` - checkout paths, environment targets, runtime copy sets, and output policy.
- `src/{can,files,harness,sign-on,command}/` - shared Node code and command dispatch.
- `src/{control,publish,host,sync,proxy,gate}/` - operator and service code.
- `server/` and `tools/` retain command entries, scripts, tests, guest programs, and platform assets.
- `lib/output.js` and `lib/output.sh` retain compatible entries into the shared output policy.

Hosted actors in two halves that do not mix:

- `tools/control/` - Node. Makes hosts exist, puts code on them, takes them away.
  Talks to the live side only over its HTTP API. Its `scripts/` are the Mac and
  Lima build/run steps.
- `server/host/` - Node, standard library only. The live code: runs on the host,
  owns actors. Its `scripts/` are the host syscalls, `guest/` runs inside an
  actor, and `clients/` are the host-shell tools (still Python).
- `tools/examples/`: standalone example apps; `static` and `app` ship in the starter.
- `tools/publish/`: builds the recipes in a harness's `apps/` and publishes them.
  Recipe `pages` selects full vault HTML by itemid and public output `path`;
  `files: [{ from, path }]` selects its CSS and scripts inside the vault.
  Page sources also publish at their itemid paths. `site.json` can enable `pwa`;
  updates wait until all pages close. Shared partials use `.fragment`.
- `tools/desktop/`: the signed download that boots pi with the harness inside.
- `frontend/`: Realness app; root `*:frontend` scripts; lint and fmt in root `vite.config.js`.
- Frontend builds, prerender, preview, and releases use `frontend_out()` in `src/settings/output.js`: normally harness `artifacts/realness/frontend/dist/`. `DIST_DIR` selects the site directory. Service staging and hosting-config generation accept an explicit output-root path for isolated builds.
- Frontend deploy commands generate Firebase config and target aliases under the output root, preserving absolute rules and secondary-site paths. Use the product frontend deploy command; no deployment is part of output cleanup.
- Dev deploy: `node tools/cli/bin/realness.js frontend deploy --env development` builds development mode and selects the development project. Add `--dry-run` to inspect the commands without execution.
- `frontend/packages/`: published @realness.online packages; linked by `file:`, publish from their folder.

The existing services use one root package and install. Internal imports use `#root/`; runtime code
for host, sync, and proxy uses only the Node standard library.
Root `npm test` first runs `check:quality`: formatting/lint, backend types, strict Fallow dead-code, and Node tests with coverage. It then runs frontend and Functions tests. A failed check stops the chain. `npm run test:node` remains the focused Node command; `npm run build` builds the frontend. Renderer dependencies use the root install.

Admins are `tel:` links in `admins.html` at the bucket root. Each new bucket needs one,
written with `gcloud storage cp`; without it `admin login` fails with `ls can://hosts/: 403`.

## Functions and ops

- `functions/` keeps its own install and Node 22 runtime.
- `tools/ops/` holds traffic, ads, repair, and migration tools. Run them from the product root; this folder has no separate package or install.
- `npm run test:functions` and `check:functions` verify Functions. `pre-commit:functions` keeps the lint-and-test gate; watch and coverage use `test:functions:*`.
- `npm run traffic -- --help` lists traffic options without cloud access.
- `firebase.functions.json` selects Functions only; frontend hosting config stays separate.
- `npm run deploy:functions -- --project <id>` deploys Functions; deployment is not part of this merge.
- `npm --prefix functions ci` installs the Functions lockfile independently.
- `npm test` includes Functions; frontend builds do not deploy them.

## Launcher export lookup

`bin/lib/product.js` reads the product export map from disk. Node caches package exports across manifest changes, so extension reload alone can retain a removed launcher path. The same-process regression is in `bin/lib/product.test.js`; an already loaded old helper can require one Pi process restart.

## Local launcher

From the harness root: `npm run local`. Starts the Lima host, worker watchers,
local gate, and frontend. `npm run local -- --dry-run` prints the commands.
The frontend starts with Vite mode `local`; `/gate` routes to the local gate.
Readiness checks the running server's `X-Vite-Mode` header. Browser gate URLs
come from `src/settings/environments.js`. Development and production browser
builds keep the current development gate; production service deployment stays
unconfigured until promotion.
The monitor reuses `realness watch` rendering and refresh keys.
Ctrl-C stops only the launcher's local child groups. The host and any reused
services stay running. `npm start` still starts Pi.
Existing frontend servers must use the local gate; stop a differently configured
server yourself before running the launcher. Sync and model proxy remain the
configured development cloud services. Logs: `artifacts/realness/local/`.

## Commands

Run from `apps/realness` with `npm run realness -- <args>`. The
environment is the first word and is required.

```
node tools/cli/bin/realness.js local  setup              # once: Lima guest, artifacts, boot check
node tools/cli/bin/realness.js local  build              # stage the harness, build the template
node tools/cli/bin/realness.js local  host up            # volume + TAP + API; waits for the seed
node tools/cli/bin/realness.js local  host restart fc-local   # the name is required
node tools/cli/bin/realness.js local  host down
node tools/cli/bin/realness.js local  host list

node tools/cli/bin/realness.js development host up <name> [--smoke]        # ~3 min, ends serving
node tools/cli/bin/realness.js development host restart <name>             # push code, re-serve
node tools/cli/bin/realness.js development host down <name>                # park, disks kept
node tools/cli/bin/realness.js development host down <name> --delete       # drain, then delete
node tools/cli/bin/realness.js development host down <name> --delete --no-drain
node tools/cli/bin/realness.js development host drain <name> [--delete]    # export and ship only
node tools/cli/bin/realness.js development probe [<type>:<zone> ...]       # what can be created now

node tools/cli/bin/realness.js local admin login|whoami|logout       # admin sign-in, checked by sync
node tools/cli/bin/realness.js local host status | actor list | loop list
node tools/cli/bin/realness.js local person <phone>                  # actors, loops, today's usage
node tools/cli/bin/realness.js local usage <phone> --day=2026-09-30
node tools/cli/bin/realness.js local limit <phone>                   # free limits, paid credit, warning
node tools/cli/bin/realness.js local actor idle|stop <id>          # obeyed on the host's next pass
node tools/cli/bin/realness.js local loop stop <id>
node tools/cli/bin/realness.js local status                         # everything, attention last; exit 2 on attention
node tools/cli/bin/realness.js local service list | logs <service> --errors --since=1h | cost --days=7
```

`realness local` reads the cloud dev sync, like the proxy's ledger. `host up` and
`restart` register the host's record key there; published sites stay on the
local sync at 18096.

Add `--json` to any command: one JSON result on stdout, progress on stderr. Phones print masked.

Host config is `tools/control/webspace.config.js`: `local` uses Lima and `development` uses Google Cloud. Shared targets live in `src/settings/environments.js`. `probe` exits non-zero when nothing can be
made, so it is usable as a check. `--fresh` is dev only: it stops the stack and
wipes the actors volume so the seed rebuilds from the current template. In prod
no `--fresh` exists - a changed template fingerprint rebuilds the seed on the
next serve, and the actors volume persists across restarts.

Deploy the proxy that hosted Pi calls for models with
`server/proxy/scripts/deploy.sh development`. Service deploy scripts require an environment; production service settings remain unconfigured. Cross-environment project, identity, and bucket overrides fail before cloud calls.

Deploy the record service - hosts and phones write through it - with
`server/sync/scripts/deploy.sh`. It scales to zero, so `realness ... status` may need
a cold start. Host alerts need a clock outside it:
`server/sync/scripts/alert-schedule.sh <webhook-url>` stores ALERT_TOKEN and the
webhook, then makes a Cloud Scheduler job that wakes sync every minute; run
`server/sync/scripts/deploy.sh` again so the secrets reach the service.

## Personal file capabilities

- `tools/cli/` adds `realness files sync` and `realness files cat`, with `--json`.
- The adapter reuses sync's authenticated client; it holds no storage keys.

## Checking a deployed host

`check:host` and `check:chat` run against a development host through a tunnel:

```
G="gcloud compute ssh <name> --zone=us-east1-b --project realness-development --quiet"
$G -- -N -L 18080:127.0.0.1:8080 -L 18081:127.0.0.1:8081 &      # kill this PID after
export HOST_PASS_SECRET="$($G --command='sudo cat /etc/realness/host-pass-secret')"
KILL="$G --command='sudo kill -9 {pid}'" node --test --test-concurrency=1 tools/control/test/host.check.js
SITE_URL=https://realness-development-sites.web.app/sites node tools/control/test/chat.check.js
```

- `host-smoke.sh` is stale: it kills the live host and serves without secrets. Use `check:host`.
- A parked host has no start command: `gcloud compute instances start <name>`, then `host restart <name>`.

## Tests

- `stage-runtime.sh` copies the actor dependency set from `src/settings/layout.js`; the template builder calls that same helper.
- `stage-host.sh` stages the host locally; cloud push sends that inspected tree. `host-stage.test.js` loads its entry and stages an actor without installed packages.
- `guest-runtime.test.js` checks the import graph and loads the staged CLI and cloud module without network reads.
- Cache-pruning tests use a separate cache and an injected clock; they must pass when run alone.

Compressed session replay uses the fork's `pi-session-read` executable.
`PI_SESSION_READER` can select a local built reader. The replay tests use
`work/pi/packages/coding-agent/dist/session-read.js`; build it first with
`npm --prefix ../../work/pi/packages/coding-agent run build` from this folder.
JSONL replay does not need that command. Hosted compressed replay requires f2.

`npm test` - the boundary check. It fails if `server/host/` refers to
`tools/control/` or imports external runtime code, or if `tools/control/` imports a host module
instead of using the API.

`npm run check:host` - the host's contract over HTTP, h3 lessons
included. Needs `realness local host up`; `API=` and `TERM_URL=` point it at
another host.

`npm run check:browser` - two headless fresh-actor runs;
`npm run check:browser:cold` - one disk-reload browser run. The cold Pi prompt
can take about 20 seconds. Both need agent-browser and a running local host.

`npm run check:boundary` - g2d: on two fresh actors, proves Pi
runs as `realness` and that user cannot touch system paths; that the internet
answers while a sibling actor, the host's address, and cloud metadata do not;
and that nothing is on disk, the door mints a model pass, and the proxy takes
it. Needs a running local host built from the current `server/host/guest/`. It spends
model tokens.

`npm run check:fresh-actor` - s1 live: a fresh actor pulls
saved files through a sync service in the Lima guest and replays pending
edits; a limited actor pulls only its paths. Needs a running local host and a
template built after changing `server/host/guest/realness-recover`.

`npm run check:actor-request` - o6 live: creates an actor, idles
then stops it through sync, deletes it. Needs a local host and `admin login`.

`npm run check:pi-exit` - a real proxy reply through Pi, then
process exit. This spends model tokens and needs a running local host.

## An actor builds and publishes a site (a1, a2, c1e)

- `/site` and `/app` copy `tools/examples/<name>` from the starter, install in the
  actor, then `realness publish dist`.
- With sync, publish uploads immutable versions to `sites/<id>/` and serves from
  sync, so the URL outlives the actor. `dev-stack.sh` runs that sync on
  `127.0.0.1:18096` and sets `SYNC_SITE_URL`; the site URL is then
  `http://127.0.0.1:18096/sites/{id}/`.
- Without `SYNC_SITE_URL`, publish falls back to `published/<id>/` served at
  `/s/{id}/` on the actor's host. That is the offline unit-test path.
- The c1e checks need a running API and sync: `realness local host up`, then
  `npm run check:site` and `npm run check:chat`.
- A changed template fingerprint rebuilds the seed on the next serve.

## Billing (b1)

- Proxy routes: `GET /limit`, `POST /pay/checkout`, `POST /pay/webhook`.
- Pay page: `https://realness-development.web.app/pay` (`src/app/views/Pay.vue`).
- Stripe setup, safe to rerun: `node server/proxy/scripts/stripe-setup.js`,
  then `server/proxy/scripts/deploy.sh` (it turns payments on when both secrets exist).
- Reconcile: `node tools/cli/bin/realness.js local reconcile`: models (ledger vs OpenRouter, today and month)
  and GCP (unexpected services, spikes; list in `cloud.expected`). Exit 2 on gaps.
  Reads the proxy's own key totals; needs that key used by nothing else. `status` runs it too.
- Store a secret without echoing it: `npm run secret -- NAME [dev|prod]`.
- Live check of the chat page's limit route: `npm run check:chat-limit`.

## Chrome VM (c1)

- Build in the Lima guest: `sudo bash /mnt/fc/tools/control/scripts/chrome-image-build.sh` -> `/opt/fc/chrome.ext4`.
- Check: `sudo node /mnt/fc/tools/control/scripts/chrome-snapshot-check.js` (`MIB=`, `URL=`); writes `result.json` and `page.png`.
- Chrome VM TAPs are `fc-chrome<n>` on 172.18; `net-up.sh` gives them internet and host access to 9222.
- Rerun `net-up.sh` with `ACTOR_HOST_PORTS="18095 18096"` while the dev stack runs, or actors lose sync.

## Known quirks (moved from learnings)

- Development is home; production waits for promotion.
- Deploy sync after path-rule changes; sync code changes run live each turn.
- The sync ignore file is `.ignore`; skip.js ignores artifacts, dist, Obsidian.
- Session history belongs in default sync; check sync before proposing site retention.
- Default Hosting site needs project delete.
- Cloud Run minScale=1 bills about $10 monthly.
- Starters ship as a versioned build, not hand-copies.
- Live tools in artifacts write `.live`.
- `work/thoughts` is the poster library; trace posters with bin scripts.
- Chat Mermaid: pass through `bin/mermaid-fit.js` first.
- npm publish web auth needs a pty; `npm view` caches, curl the registry to verify.
- git filter-repo rewrites short SHAs in messages; Claude and Cursor append credit trailers.
- pi: cursor is an inverse cell; kitty keyboard enable is `CSI >...u`.
- pi settings: quietStartup "header" keeps version only; mcpFooterStatus off hides MCP footer.
- Skill checks skip derived runtime state.
- BSD sed: the `$` anchor misses the last line.
- The Read tool caps at 50KB; verify large files with node.
- `open` takes a full path; macOS picks the app.
