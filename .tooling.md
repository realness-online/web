# brayness tooling (curated)

Hosted sessions in two halves that do not mix:

- `control/` - Node. Makes hosts exist, puts code on them, takes them away.
  Talks to the live side only over its HTTP API. Its `scripts/` are the Mac and
  Lima build/run steps.
- `orchestrator/` - Python3 stdlib. The live code: runs on the host, owns
  sessions. Its `scripts/` are the host syscalls, `guest/` runs inside a
  session, and `clients/` are the host-shell tools.
- `examples/site/` - the markdown-to-static-site builder, comark + shiki.
- `examples/plan-viewer/` - the plans viewer, built on the same builder.

No package manager at the project root; `control/` has no dependencies.

## Commands

Run from `work/brayness/control` (or `npm run webspace -- <args>`). The
environment is the first word and is required.

```
node bin/webspace.js dev  setup              # once: Lima guest, artifacts, boot check
node bin/webspace.js dev  build              # stage the harness, build the template
node bin/webspace.js dev  host up            # volume + TAP + API; waits for the seed
node bin/webspace.js dev  host restart
node bin/webspace.js dev  host down
node bin/webspace.js dev  host list

node bin/webspace.js prod host up <name> [--smoke]        # ~3 min, ends serving
node bin/webspace.js prod host restart <name>             # push code, re-serve
node bin/webspace.js prod host down <name>                # park, disks kept
node bin/webspace.js prod host down <name> --delete       # drain, then delete
node bin/webspace.js prod host down <name> --delete --no-drain
node bin/webspace.js prod host drain <name> [--delete]    # export and ship only
node bin/webspace.js prod probe [<type>:<zone> ...]       # what can be created now
```

Config is `control/webspace.config.js`: one block per environment (`dev` is
Lima on this Mac, `prod` is GCP). `probe` exits non-zero when nothing can be
made, so it is usable as a check. There is no `--fresh`: a changed template
fingerprint rebuilds the seed on the next serve, and the sessions volume
persists across restarts.

## Internals, called by control

- `control/scripts/`: `guest-setup.sh`, `boot-check.sh`, `ship-stage.sh`,
  `harness-stage.sh`, `template-build.sh`, `dev-stack.sh`.
- `orchestrator/scripts/`: `host-bootstrap.sh`, `host-smoke.sh`,
  `orchestrator-restart.sh`, `net-up.sh`, `net-down.sh`, `sessions-volume.sh`,
  `idle-guard.sh`.
- `orchestrator/guest/`: the in-session agent and its systemd units.
- `orchestrator/clients/`: `brayness-login.sh`, `pty-attach.py`,
  `vsock-exec.py`.

Run on a host by hand: `orchestrator/clients/brayness-login.sh` (one ssh login
becomes one session).

## Tests

`cd control && npm test` - the boundary check. It fails if `orchestrator/`
refers to `control/`, or if `control/` reaches into the package instead of
using the API. Proven by breaking the rule and watching it fail.

## Checks (archived)

Every per-node check script (`f3-verify.sh`, `r3a`-`r9`, `a1`, `a2`, `x1`, ...)
and its runs are in `artifacts/firecracker/webspace-archive/`. The eight Mac
operator scripts that `control/` replaces are in
`artifacts/firecracker/webspace-control-port/`. The counts and gotchas behind
each are in `README.md`.

## A session builds and publishes a site (a1, a2)

- The builder is `examples/site/` (`build.js`, `viewer.css`, comark + shiki
  pinned in its `package.json`). `ship-stage.sh` puts its source at
  `/opt/brayness/examples/site`; a session runs `npm install --prefix
/opt/brayness/examples/site`. One copy, no skill in the harness.
- Publish is `POST /v1/sessions/{id}/publish {"path": "/root/site"}`; the site
  is served at `/s/{id}/`, and in the dev loop that is
  `http://127.0.0.1:18080/s/{id}/`.
- The a1/a2 checks are in the archive and need a running API: `webspace dev host up`.
- A changed template fingerprint rebuilds the seed on the next serve.
