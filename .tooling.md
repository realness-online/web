# brayness tooling (curated)

Four folders, by who uses them:

- `frontend/` - what people use: the Realness app.
- `server/` - what machines run: `sync`, `proxy`, `gate` (Cloud Run), `host`, `lima`; `scripts/` stages and deploys them.
- `tools/` - what the operator runs: `control`, `cli`, `publish`, `desktop`, `examples`.
- `lib/` - shared code: `can` (rights, storage, passes), `sign-on`, output and websocket helpers.

Hosted actors in two halves that do not mix:

- `tools/control/` - Node. Makes hosts exist, puts code on them, takes them away.
  Talks to the live side only over its HTTP API. Its `scripts/` are the Mac and
  Lima build/run steps.
- `server/host/` - Node, standard library only. The live code: runs on the host,
  owns actors. Its `scripts/` are the host syscalls, `guest/` runs inside an
  actor, and `clients/` are the host-shell tools (still Python).
- `tools/examples/`: standalone example apps; `static` and `app` ship in the starter.
- `tools/publish/`: builds the recipes in a harness's `apps/` and publishes them.
- `tools/desktop/`: the signed download that boots pi with the harness inside.
- `frontend/`: Realness app; root `*:frontend` scripts; lint and fmt in root `vite.config.js`.
- Dev deploy: `npm run deploy:frontend:dev` builds `--mode development`, deploys `--project development`.
- `frontend/packages/`: published @realness.online packages; linked by `file:`, publish from their folder.

The existing services use one root package and install. Internal imports use `#root/`; runtime code
for host, sync, and proxy uses only the Node standard library.
Root `npm test` includes renderer, chat, and frontend tests; root `npm run build`
builds chat and terminal. Renderer dependencies use the root install.

Admins are `tel:` links in `admins.html` at the bucket root. Each new bucket needs one,
written with `gcloud storage cp`; without it `admin login` fails with `ls can://hosts/: 403`.

## Commands

Run from `work/brayness` with `npm run webspace -- <args>`. The
environment is the first word and is required.

```
node tools/control/bin/webspace.js local  setup              # once: Lima guest, artifacts, boot check
node tools/control/bin/webspace.js local  build              # stage the harness, build the template
node tools/control/bin/webspace.js local  host up            # volume + TAP + API; waits for the seed
node tools/control/bin/webspace.js local  host restart fc-local   # the name is required
node tools/control/bin/webspace.js local  host down
node tools/control/bin/webspace.js local  host list

node tools/control/bin/webspace.js development host up <name> [--smoke]        # ~3 min, ends serving
node tools/control/bin/webspace.js development host restart <name>             # push code, re-serve
node tools/control/bin/webspace.js development host down <name>                # park, disks kept
node tools/control/bin/webspace.js development host down <name> --delete       # drain, then delete
node tools/control/bin/webspace.js development host down <name> --delete --no-drain
node tools/control/bin/webspace.js development host drain <name> [--delete]    # export and ship only
node tools/control/bin/webspace.js development probe [<type>:<zone> ...]       # what can be created now

node tools/control/bin/webspace.js local admin login|whoami|logout       # admin sign-in, checked by sync
node tools/control/bin/webspace.js local host status | actor list | loop list
node tools/control/bin/webspace.js local person <phone>                  # actors, loops, today's usage
node tools/control/bin/webspace.js local usage <phone> --day=2026-09-30
node tools/control/bin/webspace.js local limit <phone>                   # free limits, paid credit, warning
node tools/control/bin/webspace.js local actor idle|stop <id>          # obeyed on the host's next pass
node tools/control/bin/webspace.js local loop stop <id>
node tools/control/bin/webspace.js local status                         # everything, attention last; exit 2 on attention
node tools/control/bin/webspace.js local service list | logs <service> --errors --since=1h | cost --days=7
```

`webspace local` reads the cloud dev sync, like the proxy's ledger. `host up` and
`restart` register the host's record key there; published sites stay on the
local sync at 18096.

Add `--json` to any command: one JSON result on stdout, progress on stderr. Phones print masked.

Config is `tools/control/webspace.config.js`: one block per environment (`dev` is
Lima on this Mac, `prod` is GCP). `probe` exits non-zero when nothing can be
made, so it is usable as a check. `--fresh` is dev only: it stops the stack and
wipes the actors volume so the seed rebuilds from the current template. In prod
no `--fresh` exists - a changed template fingerprint rebuilds the seed on the
next serve, and the actors volume persists across restarts.

Deploy the proxy that hosted Pi calls for models with
`server/proxy/scripts/deploy.sh`; it defaults to `realness-development`, beside sync.

Deploy the record service - hosts and phones write through it - with
`server/sync/scripts/deploy.sh`. It scales to zero, so `webspace ... status` may need
a cold start. Host alerts need a clock outside it:
`server/sync/scripts/alert-schedule.sh <webhook-url>` stores ALERT_TOKEN and the
webhook, then makes a Cloud Scheduler job that wakes sync every minute; run
`server/sync/scripts/deploy.sh` again so the secrets reach the service.

## Personal file capabilities

- `tools/cli/` adds `brayness files sync` and `brayness files cat`, with `--json`.
- The adapter reuses sync's authenticated client; it holds no storage keys.
- `npm run check:cli` checks extensions and exercises the public command against the local service.
- Local command setup and the result contract: `tools/cli/README.md`.
- This adapter is not installed globally or shipped in actor images yet.

## Internals, called by control

- `tools/control/scripts/`: `guest-setup.sh`, `boot-check.sh`, `ship-stage.sh`,
  `harness-stage.sh`, `template-build.sh`, `dev-stack.sh`.
- `server/host/scripts/`: `host-bootstrap.sh`, `host-smoke.sh`,
  `host-restart.sh`, `net-up.sh`, `net-down.sh`, `actors-volume.sh`,
  `idle-guard.sh`, `node-install.sh` (pinned Node, both arches).
- `server/host/guest/`: the in-actor agent and its systemd units.
- `server/host/clients/`: `brayness-login.sh`, `pty-attach.py`,
  `vsock-exec.py`.

Run on a host by hand: `server/host/clients/brayness-login.sh` (one ssh login
becomes one actor).

## Tests

`npm test` - the boundary check. It fails if `server/host/` refers to
`tools/control/` or imports external runtime code, or if `tools/control/` imports a host module
instead of using the API.

`npm run check:host` - the host's contract over HTTP, h3 lessons
included. Needs `webspace local host up`; `API=` and `TERM_URL=` point it at
another host.

`npm run check:browser` - two headless fresh-actor runs;
`npm run check:browser:cold` - one disk-reload browser run. The cold Pi prompt
can take about 20 seconds. Both need agent-browser and a running local host.

`npm run check:boundary` - g2d: on two fresh actors, proves Pi
runs as `brayness` and that user cannot touch system paths; that the internet
answers while a sibling actor, the host's address, and cloud metadata do not;
and that nothing is on disk, the door mints a model pass, and the proxy takes
it. Needs a running local host built from the current `server/host/guest/`. It spends
model tokens.

`npm run check:fresh-actor` - s1 live: a fresh actor pulls
saved files through a sync service in the Lima guest and replays pending
edits; a limited actor pulls only its paths. Needs a running local host and a
template built after changing `server/host/guest/brayness-recover`.

`npm run check:actor-request` - o6 live: creates an actor, idles
then stops it through sync, deletes it. Needs a local host and `admin login`.

`npm run check:pi-exit` - a real proxy reply through Pi, then
process exit. This spends model tokens and needs a running local host.

## An actor builds and publishes a site (a1, a2, c1e)

- `/site` and `/app` copy `tools/examples/<name>` from the starter, install in the
  actor, then `brayness publish dist`.
- With sync, publish uploads immutable versions to `sites/<id>/` and serves from
  sync, so the URL outlives the actor. `dev-stack.sh` runs that sync on
  `127.0.0.1:18096` and sets `SYNC_SITE_URL`; the site URL is then
  `http://127.0.0.1:18096/sites/{id}/`.
- Without `SYNC_SITE_URL`, publish falls back to `published/<id>/` served at
  `/s/{id}/` on the actor's host. That is the offline unit-test path.
- The c1e checks need a running API and sync: `webspace local host up`, then
  `npm run check:site` and `npm run check:chat`.
- A changed template fingerprint rebuilds the seed on the next serve.

## Billing (b1)

- Proxy routes: `GET /limit`, `POST /pay/checkout`, `POST /pay/webhook`.
- Pay page: `https://realness-development.web.app/pay` (`frontend/src/views/Pay.vue`).
- Stripe setup, safe to rerun: `node server/proxy/scripts/stripe-setup.js`,
  then `server/proxy/scripts/deploy.sh` (it turns payments on when both secrets exist).
- Reconcile: `node tools/control/bin/webspace.js local reconcile`: models (ledger vs OpenRouter, today and month)
  and GCP (unexpected services, spikes; list in `cloud.expected`). Exit 2 on gaps.
  Reads the proxy's own key totals; needs that key used by nothing else. `status` runs it too.
- Store a secret without echoing it: `npm run secret -- NAME [dev|prod]`.
- Live check of the chat page's limit route: `npm run check:chat-limit`.

## Known quirks (moved from learnings)

- Development is home; production waits for promotion.
- Deploy sync after path-rule changes; sync code changes run live each turn.
- The sync ignore file is `.ignore`; skip.js ignores artifacts, dist, Obsidian.
- Session history belongs in default sync; check sync before proposing site retention.
- Default Hosting site needs project delete.
- Cloud Run minScale=1 bills about $10 monthly.
- Starters ship as a versioned build, not hand-copies.
- Live tools in artifacts write `.live`.
- `work/thoughts` is the poster library; trace posters with bin scripts.
- Chat Mermaid: pass through `bin/mermaid-fit.js` first.
- npm publish web auth needs a pty; `npm view` caches, curl the registry to verify.
- git filter-repo rewrites short SHAs in messages; Claude and Cursor append credit trailers.
- pi: cursor is an inverse cell; kitty keyboard enable is `CSI >...u`.
- pi settings: quietStartup "header" keeps version only; mcpFooterStatus off hides MCP footer.
- Skill checks skip derived runtime state.
- BSD sed: the `$` anchor misses the last line.
- The Read tool caps at 50KB; verify large files with node.
- `open` takes a full path; macOS picks the app.
