# brayness tooling (curated)

Hosted actors in two halves that do not mix:

- `control/` - Node. Makes hosts exist, puts code on them, takes them away.
  Talks to the live side only over its HTTP API. Its `scripts/` are the Mac and
  Lima build/run steps.
- `host/` - Node, standard library only. The live code: runs on the host,
  owns actors. Its `scripts/` are the host syscalls, `guest/` runs inside an
  actor, and `clients/` are the host-shell tools (still Python).
- Examples are not here: `brayness-examples` holds them; prompts fetch them.

No package manager at the project root; `control/` has no dependencies.

## Commands

Run from `work/brayness/control` (or `npm run webspace -- <args>`). The
environment is the first word and is required.

```
node bin/webspace.js dev  setup              # once: Lima guest, artifacts, boot check
node bin/webspace.js dev  build              # stage the harness, build the template
node bin/webspace.js dev  host up            # volume + TAP + API; waits for the seed
node bin/webspace.js dev  host restart fc-local   # the name is required
node bin/webspace.js dev  host down
node bin/webspace.js dev  host list

node bin/webspace.js prod host up <name> [--smoke]        # ~3 min, ends serving
node bin/webspace.js prod host restart <name>             # push code, re-serve
node bin/webspace.js prod host down <name>                # park, disks kept
node bin/webspace.js prod host down <name> --delete       # drain, then delete
node bin/webspace.js prod host down <name> --delete --no-drain
node bin/webspace.js prod host drain <name> [--delete]    # export and ship only
node bin/webspace.js prod probe [<type>:<zone> ...]       # what can be created now

node bin/webspace.js dev admin login|whoami|logout       # admin sign-in, checked by sync
node bin/webspace.js dev host status | actor list | loop list
node bin/webspace.js dev person <phone>                  # actors, loops, today's usage
node bin/webspace.js dev usage <phone> --day=2026-09-30
node bin/webspace.js dev limit <phone>                   # free limits, paid credit, warning
node bin/webspace.js dev actor idle|stop <id>          # obeyed on the host's next pass
node bin/webspace.js dev loop stop <id>
node bin/webspace.js dev status                         # everything, attention last; exit 2 on attention
node bin/webspace.js dev service list | logs <service> --errors --since=1h | cost --days=7
```

`webspace dev` reads the cloud dev sync, like the proxy's ledger. `host up` and
`restart` register the host's record key there; published sites stay on the
local sync at 18096.

Add `--json` to any command: one JSON result on stdout, progress on stderr. Phones print masked.

Config is `control/webspace.config.js`: one block per environment (`dev` is
Lima on this Mac, `prod` is GCP). `probe` exits non-zero when nothing can be
made, so it is usable as a check. `--fresh` is dev only: it stops the stack and
wipes the actors volume so the seed rebuilds from the current template. In prod
no `--fresh` exists - a changed template fingerprint rebuilds the seed on the
next serve, and the actors volume persists across restarts.

Deploy the proxy that hosted Pi calls for models with
`proxy/scripts/deploy.sh`; it defaults to `realness-development`, beside sync.

Deploy the record service - hosts and phones write through it - with
`sync/scripts/deploy.sh`. It scales to zero, so `webspace ... status` may need
a cold start. Host alerts need a clock outside it:
`sync/scripts/alert-schedule.sh <webhook-url>` stores ALERT_TOKEN and the
webhook, then makes a Cloud Scheduler job that wakes sync every minute; run
`sync/scripts/deploy.sh` again so the secrets reach the service.

## Personal file capabilities

- `cli/` adds `brayness files sync` and `brayness files cat`, with `--json`.
- The adapter reuses sync's authenticated client; it holds no storage keys.
- `cd cli && npm run check` checks extensions and exercises the public command against the local service.
- Local command setup and the result contract: `cli/README.md`.
- This adapter is not installed globally or shipped in actor images yet.

## Internals, called by control

- `control/scripts/`: `guest-setup.sh`, `boot-check.sh`, `ship-stage.sh`,
  `harness-stage.sh`, `template-build.sh`, `dev-stack.sh`.
- `host/scripts/`: `host-bootstrap.sh`, `host-smoke.sh`,
  `host-restart.sh`, `net-up.sh`, `net-down.sh`, `actors-volume.sh`,
  `idle-guard.sh`, `node-install.sh` (pinned Node, both arches).
- `host/guest/`: the in-actor agent and its systemd units.
- `host/clients/`: `brayness-login.sh`, `pty-attach.py`,
  `vsock-exec.py`.

Run on a host by hand: `host/clients/brayness-login.sh` (one ssh login
becomes one actor).

## Tests

`cd control && npm test` - the boundary check. It fails if `host/` refers to
`control/` or takes a dependency, or if `control/` imports a host module
instead of using the API.

`cd control && npm run check:host` - the host's contract over HTTP, h3 lessons
included. Needs `webspace dev host up`; `API=` and `TERM_URL=` point it at
another host.

`cd control && npm run check:browser` - two headless fresh-actor runs;
`npm run check:browser:cold` - one disk-reload browser run. The cold Pi prompt
can take about 20 seconds. Both need agent-browser and a running dev host.

`cd control && npm run check:boundary` - g2d: on two fresh actors, proves Pi
runs as `brayness` and that user cannot touch system paths; that the internet
answers while a sibling actor, the host's address, and cloud metadata do not;
and that nothing is on disk, the door mints a model pass, and the proxy takes
it. Needs a running dev host built from the current `host/guest/`. It spends
model tokens.

`cd control && npm run check:fresh-actor` - s1 live: a fresh actor pulls
saved files through a sync service in the Lima guest and replays pending
edits; a limited actor pulls only its paths. Needs a running dev host and a
template built after changing `host/guest/brayness-recover`.

`cd control && npm run check:actor-request` - o6 live: creates an actor, idles
then stops it through sync, deletes it. Needs a dev host and `admin login`.

`cd control && npm run check:pi-exit` - a real proxy reply through Pi, then
process exit. This spends model tokens and needs a running dev host.

## An actor builds and publishes a site (a1, a2, c1e)

- `/site` and `/app` run `npx giget gh:scott-fryxell/brayness-examples/<name>`,
  install in the actor, then `brayness publish dist`. Nothing ships in the image.
- With sync, publish uploads immutable versions to `sites/<id>/` and serves from
  sync, so the URL outlives the actor. `dev-stack.sh` runs that sync on
  `127.0.0.1:18096` and sets `SYNC_SITE_URL`; the site URL is then
  `http://127.0.0.1:18096/sites/{id}/`.
- Without `SYNC_SITE_URL`, publish falls back to `published/<id>/` served at
  `/s/{id}/` on the actor's host. That is the offline unit-test path.
- The c1e checks need a running API and sync: `webspace dev host up`, then
  `npm run check:site` and `npm run check:chat`.
- A changed template fingerprint rebuilds the seed on the next serve.

## Billing (b1)

- Proxy routes: `GET /limit`, `POST /pay/checkout`, `POST /pay/webhook`.
- Pay page: `https://brayness-sign-on.web.app/pay` (sign-on `src/pay.vue`).
- Stripe setup, safe to rerun: `node proxy/scripts/stripe-setup.js`,
  then `proxy/scripts/deploy.sh` (it turns payments on when both secrets exist).
- Reconcile: `node bin/webspace.js dev reconcile`: models (ledger vs OpenRouter, today and month)
  and GCP (unexpected services, spikes; list in `cloud.expected`). Exit 2 on gaps.
  Reads the proxy's own key totals; needs that key used by nothing else. `status` runs it too.
- Store a secret without echoing it: `cd control && npm run secret -- NAME [dev|prod]`.
- Live check of the chat page's limit route: `cd control && npm run check:chat-limit`.
